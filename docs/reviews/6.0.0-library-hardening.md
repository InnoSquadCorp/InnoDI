Two CI corrections follow from this execution and source-contract inspection:

- **LR-F05 — diagnostic artifact collision.** Fast PR and exhaustive jobs both
  execute on release-validation PRs, but uploaded the same immutable report
  names. The pinned upload action's [documented contract](https://github.com/actions/upload-artifact/blob/043fb46d1a93c77aae656e7c1c64a875d1fc6a0a/README.md#not-uploading-to-the-same-artifact)
  rejects that collision. Fast PR names now end in `-fast-pr`; exhaustive
  canonical names are preserved. Neither report is overwritten or discarded.
  The new regression recorded four failed assertions before the change and
  passes afterward. The failed CI run never reached the duplicate upload;
  its timeout must not be misreported as an artifact-service failure.
- **LR-F06 — cross-test executor interference.** Synchronous compiler/CLI
  fixtures share execution resources with timed async tests. An isolated probe
  uses byte-identical `DIAsyncScope.swift` and retry tests, plus an independent
  70-second subprocess wait. A restricted cooperative pool reproduces roughly
  70-second test scheduling delays; explicit `--no-parallel` keeps the retry
  suite around 0.005 seconds and 1,000 retry/close iterations below 0.1 seconds.
  A controlled five-second diagnostic latency assertion fails at 70.102
  seconds with parallel scheduling and passes at 0.077 seconds with independent
  cases serialized (`executor-final-red-swift63.log` /
  `executor-final-green-swift63.log`). That probe-only assertion does not replace
  or change the repository's existing one-minute test limit.
  Complete-suite coverage, fast PR and sanitizer invocations now serialize
  **independent test cases**. Tests' internal concurrent tasks, overlapping
  retries, 100-waiter stress and sanitizer instrumentation are unchanged.
  No test is removed, no timeout increased and no coverage floor reduced.
  The tradeoff is less parallelism between independent tests, not weaker
  concurrency assertions inside them.

The probe uses separately installed Swift 6.3.3 with the available macOS 26.5
SDK; it is mechanism evidence, not a substitute for exact Xcode 26.6 CI or its
