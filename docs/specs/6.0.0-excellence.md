# InnoDI 6.0.0 — 여덟 가지 개선의 완료 계약

## 문서 상태와 범위

- 상태: **Draft**. 사용자는 여덟 개선 방향을 모두 작업할 계획을 요청했다. 아래 세부 계약과 기술 설계의 승인을 받은 것으로 간주하지 않는다.
- 구현 기준: 2026-09-06 검증된 코드 후보 `f1a3eaccf19bfc43164de3621c9197c731d92342`와 검증 보강을 포함한 프로모션 head `2da86f755856eb493ee27c7aec31990772edfb09`. 로컬 exhaustive/sanitizer/소비자 gate와 프로모션 head의 원격 Examples, Docs, fast/exhaustive/sanitizer/Swift 6.2/Xcode 27/platform/path-identity lane이 통과했다. post-merge exact-SHA consumer와 exact-tag 원격 gate는 아직 실행 전이며, RFC 승인이나 배포 완료를 뜻하지 않는다.
- 기술 실행 계획: [6.0.0 excellence implementation plan](../plans/6.0.0-excellence.md).
- 기존 [RFC 0006](../rfcs/0006-assisted-subgraphs-and-container-roles.md)의 `FR-600-*` / `AC-600-*`를 유지한다. 이 문서는 추가 계약이며 기존 문서를 승인·완료 상태로 변경하지 않는다.
- 여덟 항목은 모두 Must 범위다. 구현상 어려움이 생겼다는 이유로 임의로 다음 버전으로 미루거나 조용히 축소하지 않는다. 제품 계약 변경은 사용자에게 근거와 대안을 제시해 결정한다.
- 정식 release/upgrade notes의 단일 출처는 계속 [RELEASING.md](../../RELEASING.md)다.

### 작업 가정

- Swift 6.2 최소 지원과 현재 Apple deployment floor를 유지하는 방향으로 먼저 설계한다. 변경이 필요하면 근거와 이주 비용을 별도로 승인받는다.
- 기존 eager shared 동작은 유지하고 on-demand 생성은 명시적 선택으로 추가한다.
- API 이름, 신규 product 이름, graph schema 번호는 기술 검증 전까지 후보일 뿐이다.
- InnoSample을 기준 소비자로 삼고 BlPia와 Lynceus를 committed branch pilot으로 검증한다. Mulbyul Apple은 사용자 지시에 따라 소스 변경 없이 읽기·테스트 증거만 유지한다.

### Non-goals

- 런타임 서비스 로케이터, reflection/module 자동 검색, 등록 순서에 의존하는 graph 구성.
- 이미 생성된 shared 객체의 내부 의존성을 TaskLocal override가 소급 변경하는 것처럼 보이게 하는 동작.
- 기존 live graph의 일부 캐시만 바꿔 서로 다른 세대의 의존성이 섞이는 재시도.
- actor/Sendable 진단을 끄거나 검증을 우회해 기능을 지원하는 방식.
- 임의 사용자 서비스가 내부적으로 만든 모든 작업을 강제로 취소한다고 보장하는 것.
- 이 계획 작성만으로 제품 코드 변경, 소비자 dependency upgrade, push, tag 또는 release publication을 실행하는 것.

검토 시 다음 반례 구현을 명시적으로 탈락시켜야 한다.

- on-demand라고 이름 붙였지만 dependency를 init에서 미리 만드는 구현.
- 취소된 대기자 때문에 모든 사용자의 shared 작업을 중단하는 구현.
- State 값은 유지하면서 View init마다 버려질 child를 새로 만드는 구현.
- Sendable mock이라는 이유로 검증되지 않은 unchecked conformance만 붙이는 구현.
- 서로 다른 모듈의 map 키 충돌을 런타임 last-wins로 숨기는 구현.
- debugger가 schema에 없는 정보를 unchanged/healthy로 처리하거나 opaque factory의 내부 참조를 안다고 표시하는 구현.
- doctor가 검사 중 파일을 수정하거나 migration patch가 사용자 변경을 덮는 구현.
