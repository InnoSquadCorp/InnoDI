# RFC 0005 — 5.0 contract hardening

- **Status**: Accepted
- **Authors**: InnoDI maintainers
- **Created**: 2026-07-14
- **Last updated**: 2026-07-15
- **Target release**: 5.0.0
- **Supersedes**: RFC 0004's `concrete:` inference and token-form proposal

## Summary

InnoDI 5.0 is a contract-hardening release. It restores the public guarantees
already described by the package, makes unsupported configurations fail with
InnoDI diagnostics, and moves build-time graph validation from package-wide
text scanning to target- and module-aware analysis.

All necessary source-breaking corrections land in one major release. The work
still lands on `main` as small, independently green commits so each change can
be reviewed, reverted, and measured without a big-bang rewrite.

The stable release remains 4.3.0 until the complete 5.0 release-candidate gate
passes. Documentation must not point consumers at an unreleased 5.0 tag.

## Problem definition

The 4.3.0 implementation is strong on its tested, non-generic struct path, but
the repository's snapshot-heavy test strategy does not prove every public
contract in an external SwiftPM module. The July 2026 audit found several
places where a local build can pass while the documented consumer operation
fails or validation silently misses an edge:

- the documented public `@DIComponent` example does not compile externally;
- `@DIContainer(mainActor: true)` does not isolate every original and
  generated API that exposes a dependency;
- build-time DAG validation misses supported construction syntax and complete
  `@Provide` member declarations inside conditional-compilation blocks;
- package-wide plugin scanning mixes unrelated targets, tests, and examples;
- invalid scope and effect combinations can silently fall back or surface as
  secondary Swift compiler errors;
- graph identity and JSON semantics depend on source paths rather than module
  identity;
- advertised CLI and prebuilt-distribution paths are not both usable by a
  fresh external package;
- performance and release gates can succeed without enforcing the intended
  toolchain or before a tag becomes visible to SwiftPM.

These are trust-boundary failures for a compile-time DI framework. New feature
work must not take priority over closing them.

## Constraints

- Swift tools 6.2 remains the package manifest baseline during development.
- Swift 6.2 and the current Swift 6.3 toolchain must both be represented by
  external consumer fixtures.
- Every commit on `main` must build and pass the relevant focused tests before
  the full strict-concurrency gate runs.
- Parser, macro expansion, build support, graph semantics, diagnostics, and
  documentation must change together when they express the same contract.
- Unsupported source must fail closed with a stable InnoDI diagnostic; it must
  not silently change scope, disappear from a graph, or crash the validator.
- Source paths and line numbers are diagnostic metadata, not semantic graph
  identity.
- A release tag may be created only after the same commit passes the complete
  release-candidate gate.

## Release classification

5.0 release notes distinguish two categories. Both can require consumer
changes, but they describe different compatibility intent.

### Contract-restoring behavior corrections

These changes make an already documented contract true:

- external compilation of the basic public `@DIComponent` shape;
- complete `mainActor: true` isolation propagation;
- explicit sibling-edge extraction from root factory-closure parameters and
  literal canonical `\Self.member` `with:` key paths;
- fail-closed handling of conditional provider attributes and complete
  `@Provide` member declarations inside `#if`;
- literal scope validation and effect-aware dependency validation;
- correct optional function types and generated access control;
- complete empty-container scaffolding;
- target-scoped plugin analysis and crash-free duplicate diagnostics;
- an installable public graph command or documentation that explicitly marks
  a command as repository-maintainer-only;
- fail-closed performance enforcement and pre-tag release validation.

### Intentional 5.0 breaking changes

These changes intentionally narrow or replace a public contract:

1. **Supported declaration matrix.** The initial 5.0 contract supports
   non-generic `struct` declarations at file scope or nested in non-generic
   nominal declarations for `@DIContainer` and `@DIComponent`. Classes, actors,
   enums, protocols, extension declarations, direct generic declarations,
   declarations in an enclosing generic nominal context, structs nested inside
   extensions, and declarations in executable scopes receive dedicated
   diagnostics until a future RFC proves their complete initialization,
   lookup, identity, and isolation semantics.
   Current Swift toolchains omit computed-property accessor ancestry from the
   attached-macro context, so the build plugin and graph CLI full-source
   preflight own that edge case. Swift may also add its own diagnostic when a
   local declaration carries an attached-extension macro such as
   `@DIComponent`; without full-source preflight, stacked companion macros can
   emit secondary diagnostics for an accessor-local declaration.
2. **`concrete:` removal.** The declared property type is the single source of
   truth for generated storage. `ConcreteType` produces concrete storage and
   `any Protocol` produces existential storage. The validation-only
   `concrete:` escape hatch is removed; no replacement positional token is
   added.
3. **Deprecated `@DIFeatureRoot` removal.** Consumers use
   `@SubContainer(featureRoot:)` or `featureRoots:` introduced in 4.3.0.
4. **Graph JSON schema v2.** Node identity becomes module-qualified and stable
   across checkout-root and file moves. Target scope and root pruning become
   explicit CLI inputs.
5. **Plain provider declarations.** Public `@Provide` is supported only on a
   direct, plain, stored instance `var` in the same supported `@DIContainer`
   struct. `let`, computed or observed properties, `lazy`, `weak`, `unowned`,
   `static`/`class`, standalone declarations, and declarations nested below a
   container member are rejected. Property wrappers, conditional or unknown
   attributes, setter access controls, and every source-written property-level
   global-actor attribute are also rejected, including `@MainActor`. Actor
   isolation is requested with `@DIContainer(mainActor: true)`. Any
   isolation attributes InnoDI generates on provider declarations and
   accessors are internal compiler support. InnoDI owns any accessor macro
   attached to a valid provider; consumers must not attach generated accessor
   support manually. A complete
   provider member inside `#if` receives a dedicated diagnostic. A property
   accepts exactly one `@Provide`; duplicate attributes fail closed. Direct
   provider properties must also have unique names, and every root factory
   closure parameter must have a unique effective dependency name across hard,
   `Lazy<T>`, and `Provider<T>` edges. Provider properties, factory dependency
   parameters, and `@SubContainer` properties use unescaped identifiers;
   backtick spellings are rejected before identity-based code generation.
   Opaque `some Protocol` and implicitly
   unwrapped `T!` provider property types are rejected in favor of
   `any Protocol` and explicit `T` / `T?`.
6. **Explicit sibling-edge syntax.** A provider creates sibling DI edges only
   from named parameters on the root `factory:`/`asyncFactory:` closure literal,
   or from `Type.self` combined with a literal `with:` key-path array whose
   entries use exactly the canonical direct-member spelling `\Self.member`,
   such as `[\Self.config]`; `[]` is also valid. Named container,
   module-qualified, and typealias roots are rejected, as are nested
   components, optional chaining, subscripts, and computed elements. `with:`
   targets synchronous providers only.
   Non-closure `factory:` expressions and property initializers are opaque,
   zero-edge construction sources. They must not refer to sibling container
   members; use a root closure parameter for DI wiring, or a qualified
   global/static symbol for construction that has no DI edge.
7. **Closed construction-source matrix.** A `.shared` or `.transient` provider
   declares exactly one of `factory:`, `asyncFactory:`, `Type.self`, or a
   property initializer. An `.input` provider declares none of those sources
   and does not use `with:`. `with:` is valid only with `Type.self`.
8. **Eager input function contract.** Generated `.input` initializer
   parameters remain eager values of the declared type `T`, preserving normal
   Swift `try` / `await` argument evaluation. Direct non-optional function type
   spellings are detected and emitted as escaping parameters automatically.
   A non-optional function type hidden behind a typealias uses the additive
   literal opt-in `@Provide(.input, escaping: true)`. The option is invalid for
   other scopes and obvious nonfunction or optional-function shapes. Alias
   resolution remains compiler-owned, so Swift may add a diagnostic when a
   conservatively accepted alias does not resolve to a non-optional function.

Any additional breaking proposal must be accepted and implemented before the
5.0 release-candidate freeze. Otherwise it moves to a future major release;
5.x does not introduce a second silent breaking window.

## Decisions

### External consumer compilation is authoritative

Macro snapshots remain the fast inner loop, but public API acceptance requires
a fresh SwiftPM consumer that imports the public product and invokes the real
Swift compiler with complete strict concurrency and warnings as errors.

Fixtures cover both compile-pass and compile-fail contracts. A failing fixture
must assert the intended InnoDI diagnostic and reject validator traps, stack
dumps, timeouts, and unrelated package-resolution failures.

### Isolation belongs to the whole generated surface

`mainActor: true` applies to original dependency accessors and every generated
entry point that reads, creates, overrides, mounts, or exposes them. This
includes every initializer, `Overrides`, the `applyOverrides` function types
used by convenience initializers, `withOverrides`, child overrides, and
component mounting, all four `withOverrides` operation closures, and
feature-root helpers. For `@DIComponent`, the generated
`<Container>Dependencies` protocol and `init(dependencies:_:)` are isolated,
and the component conforms to the dedicated
`_InnoDIMainActorComponentMountable` protocol. Ordinary components continue to
use the nonisolated `_InnoDIComponentMountable` protocol. This 5.0 split lets a
generic actor-aware mounting helper retain an `@MainActor` override-closure
type instead of weakening it to satisfy the ordinary marker. Non-`Sendable`
generated values stay on the main actor: callers should be `@MainActor` or
construct and consume those values inside `MainActor.run`. Direct `await` is
appropriate when the isolated operation returns a `Sendable` result, such as a
`withOverrides` operation result, not for carrying the container itself off
actor.

For containers without `mainActor: true`, the generated `async` and
`async throws` `withOverrides` methods and their operation closure types use
`nonisolated(nonsending)`. This keeps execution on the caller's actor executor
and prevents arbitrary non-`Sendable` containers or closures from crossing an
isolation boundary. Synchronous overloads are unchanged. The main-actor
overloads remain `@MainActor` rather than adopting the caller-isolated form.

### Validation fails closed

- A missing scope defaults to `.shared`; an unparseable supplied scope is an
  error.
- Public `@Provide` accepts only a direct, plain, stored instance `var` in the
  supported container. Unsupported storage, accessor, modifier, placement, or
  a manually attached generated accessor produces a stable InnoDI diagnostic.
- Property wrappers, conditional or unknown attributes, setter access control,
  and every source-written property-level global-actor attribute on providers
  fail closed, including `@MainActor`. Actor isolation comes from
  `@DIContainer(mainActor: true)`; isolation attributes generated on provider
  declarations and accessors are internal compiler support.
- Each provider property carries exactly one `@Provide`; duplicate attributes
  fail before peer storage generation. Provider property identities and root
  factory-parameter dependency names are unique; duplicates receive stable
  diagnostics before validation constructs name-indexed lookups. Those names,
  plus `@SubContainer` property names, are unescaped identifiers. Opaque
  `some Protocol` and implicitly unwrapped `T!` property types are rejected;
  use existential `any Protocol` and explicit `T` / `T?`.
- `.shared` and `.transient` require exactly one construction source from the
  four-source matrix; `.input` requires none and rejects `with:`.
- `.input` initializer parameters are eager `T` values. Direct non-optional
  function spellings receive escaping parameters automatically; aliases use
  literal `escaping: true`. The option fails closed outside `.input` and for
  obvious nonfunction/optional-function shapes. The compiler remains the
  authority for whether an accepted alias resolves to a non-optional function.
- Only root factory-closure parameters and literal canonical `\Self.member`
  `with:` key paths declare
  sibling edges. Nested closure parameters and identifier scanning never add
  edges. Non-closure factory expressions and property initializers are opaque
  and must not capture sibling members.
- Factory effects are explicit, not inferred. A synchronous consumer cannot
  depend on an asynchronous provider, and a nonthrowing consumer cannot depend
  on a throwing provider. These checks run for every explicit sibling edge,
  including in containers that set `validateDAG: false`.
- A complete `@Provide` member declaration inside a container's top-level
  `#if` block is rejected with a dedicated diagnostic. Conditional or unknown
  attributes on an otherwise unconditional provider are rejected by the
  closed declaration-shape contract. This RFC does not reject every unrelated
  DI attribute under conditional compilation.
- Unsupported declaration kinds and ambiguous module resolution are InnoDI
  diagnostics, not downstream Swift errors or process traps.

### Workspace and container graphs are separate

The analysis model has two layers:

```text
WorkspaceModuleGraph
  -> target and module dependency visibility

ContainerGraph
  -> containers and construction edges inside that visibility
```

The SwiftPM build plugin supplies an analysis manifest built from target source
files and recursive target dependencies. Manual CLI analysis may parse a
workspace manifest as a fallback, but both routes use the same resolver.

The schema-v2 identity is:

```text
swiftpm:<package-identity>:<module-name>::<semantic-declaration-path>
```

### Distribution claims must be executable

The source build plugin remains the supported validation distribution for
5.0. A public graph command must be exposed as a SwiftPM product or
user-invokable command plugin and proven from a fresh consumer.

The prebuilt validation package is not a 5.0 deliverable. It may return in a
future release only after measured source-build cost justifies its operational
surface and source/prebuilt parity is continuously tested.

### Release gates are monotonic

PR validation is the fast subset, `main` repeats the required gate, and the
release-candidate matrix is a strict superset. Enforcement modes fail when a
baseline, toolchain, or required artifact is missing. The release workflow
creates an immutable tag only after the approved commit passes every gate.

## Implementation sequence

1. Record this 5.0 contract and keep 4.3.0 as the stable installation version.
2. Add external SwiftPM compile-pass and compile-fail contract fixtures.
3. Restore `@DIComponent` and define the supported declaration matrix.
4. propagate MainActor isolation across original and generated APIs.
5. Harden scope, effects, optional types, access control, and empty containers.
6. Close construction-edge and conditional-provider false greens.
7. Introduce a shared module graph and target-scoped plugin manifest.
8. Adopt module-qualified identity, crash-free resolution, JSON v2, and an
   explicit CLI scope contract.
9. Remove the accepted 5.0 deprecated/validation-only surface.
10. Align documentation, platform CI, performance enforcement, and pre-tag
    release automation.
11. Run the complete release-candidate matrix before creating 5.0.0.

Every step lands as an independently green commit. A reproducer and its fix
ship together; `main` does not carry intentionally failing tests between
commits.

## Alternatives considered

### Ship corrections across 4.3.x and 4.4

Rejected. Correct actor isolation, fail-closed diagnostics, the declaration
matrix, and graph schema can reject or reinterpret currently accepted source.
Splitting them across patch and minor releases creates multiple migration
windows and makes the generated macro surface harder to reason about.

### Rewrite the macro and validator in one change

Rejected. A big-bang rewrite obscures which correction caused a regression,
makes snapshots difficult to review, and prevents safe reverts. The accepted
release train is broad; the commits inside it remain narrow.

### Continue feature development and harden later

Rejected. The framework's main value is compile-time trust. Adding more macro
surface before external-compilation and graph-validation gaps are closed
increases the amount of unproven contract that 5.0 would have to freeze.

## Failure behavior

When analysis cannot prove a supported configuration, it emits a structured
diagnostic and does not synthesize misleading code or a successful graph. User
source must never make the validator terminate via `fatalError`, duplicate-key
trap, signal, or unchecked force operation.

An unavailable optional reporting service may remain report-only. A required
correctness or release gate must fail closed and explain the missing evidence.

## Validation plan

5.0 is releasable only when all of the following are true:

- the documented public component and container examples compile externally;
- off-actor access to a main-actor container fails with the expected
  diagnostic, while explicit actor hops compile;
- non-main-actor `async` / `async throws` `withOverrides` methods and operation
  closures preserve the caller's actor executor with
  `nonisolated(nonsending)`, including for arbitrary non-`Sendable` values;
- root factory-closure parameters and literal canonical `\Self.member` `with:` key paths
  produce the intended semantic edges, while non-closure factories and
  property initializers remain zero-edge sources;
- every `.shared`/`.transient` provider has exactly one construction source,
  every `.input` has none, and `with:` appears only with `Type.self` and
  synchronous providers;
- explicit-edge effect mismatches fail with `validateDAG: true` and
  `validateDAG: false`;
- property wrappers, conditional/unknown attributes, setter access controls,
  and every source-written property-level actor attribute fail explicitly,
  including `@MainActor`; actor isolation is requested through
  `@DIContainer(mainActor: true)`;
- duplicate `@Provide` attributes, duplicate provider names, duplicate root
  factory-parameter dependency names, backtick-escaped provider/factory/
  SubContainer identifiers, opaque `some Protocol`, and implicitly
  unwrapped `T!` provider types fail with dedicated stable diagnostics;
- eager `.input` arguments continue to compile with `try` / `await`; direct
  function spellings and typealiases marked `escaping: true` store safely,
  while invalid scope/type shapes receive `provide.escaping-invalid-scope` or
  `provide.escaping-nonfunction-type`;
- complete `@Provide` member declarations inside `#if` fail explicitly rather
  than producing a green empty graph;
- production validation ignores unrelated tests/examples and includes the
  target's visible dependency closure;
- cross-module duplicate names are separated, while duplicate semantic
  identities fail without a process crash;
- moving a source file or checkout root preserves schema-v2 node and edge IDs;
- every public command and installation snippet runs from a fresh package;
- minimum/current toolchains and declared Apple platforms pass their assigned
  PR, nightly, and release matrix;
- performance enforcement cannot skip a mismatched baseline successfully;
- a failed release-candidate job creates no tag.

## Migration outline

- Replace `concrete: true` and `concrete: false` by deleting the argument and
  expressing the intended storage with the property type.
- Replace `@DIFeatureRoot` with `@SubContainer(featureRoot:)` or
  `featureRoots:`.
- Convert non-struct, generic, enclosing-generic, extension-nested, and
  executable-scope container declarations to a file-scope or nominally nested
  non-generic struct boundary, passing generic/runtime values as `.input`
  dependencies.
- Keep non-`Sendable` `mainActor: true` values in an `@MainActor` caller or a
  `MainActor.run` block; use direct `await` only for isolated operations that
  return a `Sendable` result. Update generic component mounting helpers with a
  separate `@MainActor` `_InnoDIMainActorComponentMountable` overload whose
  override parameter is `@MainActor`.
- For containers without `mainActor: true`, keep asynchronous `withOverrides`
  work on the caller's isolation. The generated async methods and operation
  closure types are `nonisolated(nonsending)`, so do not add `Sendable` merely
  to move the container or closure across an actor boundary. Synchronous
  overloads remain unchanged.
- Replace dynamic scope expressions with a scope literal.
- Move every `@Provide` to a direct, plain, stored instance `var` in its
  supported `@DIContainer`; remove `let`, accessor/observer blocks, `lazy`,
  `weak`, `unowned`, `static`/`class`, property wrappers, conditional/unknown
  attributes, setter access controls, and every source-written property-level
  actor attribute, including `@MainActor`. Request isolation with
  `@DIContainer(mainActor: true)` and never attach `_InnoDIProvideAccessor`
  manually. Isolation attributes generated on provider declarations and
  accessors are internal compiler support.
- Keep exactly one `@Provide` on each property. Replace `some Protocol` with
  `any Protocol`, and replace `T!` with explicit `T` or `T?`. A deliberately
  forged compiler-support accessor/property-wrapper combination may also
  receive Swift structural diagnostics alongside InnoDI's stable misuse code.
- Keep `.input` call sites eager; `try` / `await` expressions remain ordinary
  initializer arguments. Direct non-optional function types need no option.
  Add literal `escaping: true` only when a non-optional function type is hidden
  behind a typealias. Remove it from non-input scopes and optional/nonfunction
  shapes, and expect Swift to diagnose an alias that does not resolve to a
  non-optional function.
- Give each `.shared`/`.transient` provider exactly one of `factory:`,
  `asyncFactory:`, `Type.self`, or a property initializer. Remove all four and
  `with:` from `.input` providers. Use `with:` only with `Type.self`.
- Express sibling DI wiring with named parameters on the root `factory:` or
  `asyncFactory:` closure literal, or with `Type.self` plus a literal,
  canonical direct-member `with:` key-path array such as `[\Self.config]` or
  `[]`. Named container, module-qualified, and typealias roots, nested
  components, optional chaining, subscripts, and computed elements are
  rejected. Ensure every `with:` target is synchronous. Rewrite a non-closure
  factory or property initializer that reads a sibling as a root factory
  closure. Keep a zero-edge expression only when it uses a qualified
  global/static construction symbol.
- Declare consumer effects explicitly: use `asyncFactory:` for asynchronous
  edges and an `async throws` closure for throwing edges. Do not rely on
  `validateDAG: false` to bypass effect compatibility.
- Move complete `@Provide` member declarations out of `#if`; branch inside the
  factory or injected implementation. Remove conditional attribute blocks from
  provider declarations.
- Update graph JSON consumers to schema v2 and select target/root-pruning scope
  explicitly.

The final migration guide and codemod are release blockers, not follow-up
documentation.

## Out of scope for 5.0

- merging `@DIComponent` into `@DIContainer`;
- implicit `@DIHierarchyRoot` activation;
- removing `@DIEnvironmentBridge`;
- promoting `@GenerateMock` to GA without its existing criteria;
- scoped TaskLocal overrides;
- publishing a prebuilt validator;
- a full provider/member dependency graph beyond the supported container
  composition contract;
- relaxing the SwiftSyntax constraint without a resolver and compiler matrix.
