# InnoDI 7.0.0 — 감사 후속 통합 실행 계획 (v3)

Status: 소유자가 2026-09-29에 7.0.0 단일 트레인과 결정 D-1~D-6의 권고 채택을 확정했다. 구현·머지·태그·릴리스 승인은 아니다.
Baseline: `249e26703ab285092fd717896e48bba2d87a4533` (`main`, 6.0.0 공개 직후).
6.0.0 GitHub Release는 immutable 상태로 유지되며 7.0.0이 이를 대체한다. 6.0.0 태그를 옮기거나 재배포하지 않는다.

## 0. 배경과 변경 이력

- 2026-09-29 전체 감사(부록 A)에서 P0 없음, P1 3건(CI 피드백 시간, eager `asyncFactory` 수명, 채택·유지 비용), P2 8건이 나왔다. 매크로 우선 설계 평가에서는 키 패스 표기 불일치, `@GenerateMock` 문자열 조립, 구문 전용 전체 소스 재파서의 한계가 추가됐다.
- v1은 6.0.1/6.1.0/7.0.0으로 나눴고, v2는 6.1.0 통합에 7.0.0 전환 목록을 붙였다. v3는 7.0.0 단일 트레인이다. 근거는 세 가지다. 6.0.0을 핀한 소비자가 없다(내부 프로젝트는 3.0.1 13개, 4.3.0 1개, 5.1.0 2개). 6.0.0·5.1.0·5.0.0 릴리스가 immutable이라 재배포가 불가능하다. 브레이킹 전환은 SemVer와 RFC 규칙상 major가 필요하다.
- CI 기준선 정정: 일반 PR은 `Fast PR contracts` 한 job 15분(테스트 11.9분)이다. main push와 `release-validation` 라벨 PR은 병렬 job 기준 34–40분이며 병목은 clean coverage gate 26–30분, Swift 6.2 호환 계약 28분, TSan 16분이다. 2026-09-28 라벨 PR에서 매크로 성능 게이트가 baseline min 227.4ms 대비 293.1ms(+28.9%)로 실패했고 동일 코드 계열이라 러너 편차로 분류한다.

## 2. 범위

7.0.0에는 §3의 A–G가 모두 들어간다. 공개 API 제거·변경은 G(브레이킹 전환)에만 있고, 각 항목은 RFC 0009 마이그레이션 절, `MigrationGuide.md`의 "6.x → 7.0" 절, `InnoDI-Migrate` 멱등 재작성 규칙을 동반해야 한다.

| 구분 | 항목 |
|---|---|
| 브레이킹 전환(G) | M1 `@_exported import SwiftUI` 제거 · M2 macOS 14 바닥값과 `DIContainerHostOwner` Observation 전환 · M3 `\TypeName.x` 거부(G1에 통합) · M4 `ContainerRole` enum 복귀(컴파일러 수정이 Swift 6.2 최소 툴체인에서 확인될 때만) |
| 7.0.0에서 제외 | 의미 검증기 기본 활성(7.1 이후, 옵트인은 X1 결과에 따라 포함) · `@GenerateMock` GA(ROADMAP 기준 별도) · scoped TaskLocal 오버라이드(RFC 0003) · 최소 툴체인 상향 |

밑줄 접두 생성 지원 멤버(`_innoDITraceOwner_<member>`, 인라인 `_InnoDIDeferredCell`)의 형태 변경은 소비자가 참조할 수 없는 컴파일러 지원으로 분류해 CHANGELOG에 별도 항목으로 적는다.

### D. 기능(스냅샷 묶음 3)

**R1. `asyncFactory` on-demand와 종료 경로(D-4)**

- 위치: `Sources/InnoDIMacros/DiagnosticTypes.swift`(`provide.ondemand-async-unsupported`), `Sources/InnoDIMacros/SyntaxBuilders.swift`(Task 기반 init 빌더), `Sources/InnoDIMacros/ProvideAccessorMacro.swift`, `Sources/InnoDIBuildSupport/ContainerSemanticValidationRules.swift`(미러 규칙), `Sources/InnoDI/DIAsyncScope.swift`, `Sources/InnoDIMacros/DIContainerGeneratedNameValidation.swift`.
- 설계: 새 런타임 `_InnoDIAsyncSharedCell<Value: Sendable>`(내부 `DIAsyncScope`)을 `.onDemand` async 스토리지로 쓴다. 복사본은 셀을 공유한다(`_InnoDISharedCell` 규칙과 동일). 접근자는 첫 `await`에서 시작하고 `try await`로 취소·closed를 전파한다. 해당 제공자가 하나라도 있으면 `closeAsyncProviders()`를 생성하고 이름 충돌은 생성 이름 검증에 추가한다. eager async는 바꾸지 않는다.
- 순서: RFC 0008 초안(문제·API·대안·"마이그레이션 없음") → 진단 제거·생성 → BuildSupport 규칙 동기화 → 스냅샷(`DIContainerConfigurationMacroTests`) → 런타임 테스트(`OnDemandRuntimeTests`, `DIAsyncScopeTests` 패턴: 취소·재시도·close·복사본 공유) → 그래프 JSON `initialization` 값 재사용으로 스키마 불변 확인(`--check-contract`) → DocC `AsyncPreparation.md`, `Provide.md`, `DiagnosticsGuide.md` → 공개 API 베이스라인 갱신.
- 완료 기준: `@Provide(.shared, initialization: .onDemand, asyncFactory:)` 컴파일. `.transient` 서브컨테이너 100회 읽기에 Task 시작 0건을 트레이스로 단언. `closeAsyncProviders()` 후 접근이 `DIAsyncScopeError.closed`.
- 규모: 6–8일.

## 5. 7.0.0 종료 기준

- 후보 SHA에서 `Macro Tests` 전 job, `Release Gate`, `Remote Consumer Smoke`, `Examples`, `Docs` 통과. 성능 게이트는 main `--enforce` 기준.
- `Tools/check-public-api.py` diff의 제거·변경이 RFC 0009에 열거된 항목(`ObservableObject` 적합성, `objectWillChange`, 매크로 시그니처 변경 시 `role:` 타입)과 정확히 일치하고, 추가 심볼(`_InnoDIDeferredCell`, `_InnoDIAsyncSharedCell`, `closeAsyncProviders`)만 그 밖에 존재.
- RFC 0008·0009 Accepted. RFC 0007은 `--semantic`을 포함한 경우 Accepted, 아니면 Draft.
- `CHANGELOG.md`에 `## 7.0.0` 절이 "Breaking or Behavior Changes"와 "Upgrade Actions" 하위 절을 갖고, 6.0.0 대체 사실과 밑줄 접두 생성 지원 멤버 변경을 명시.
- `MigrationGuide.md` "6.x → 7.0" 절과 `InnoDI-Migrate --report`가 M1·G1·M4(조건부) 규칙을 인벤토리하고 `--apply`가 멱등.
- `Tools/extract-release-notes.sh 7.0.0`과 `validate-release-candidate.sh`가 새 파일 경로로 통과.
- InnoSample을 후보 SHA에 고정해 Migrate 적용 후 빌드·테스트 통과. 적용 diff가 마이그레이션 가이드 범위 안에 있어야 한다.
- 커버리지 바닥값 통과, `Tools/check-localized-readme-sync.sh`가 ko/en 기준으로 통과, `SECURITY.md` 지원 라인 `7.x`, README 버전 문서 링크 7.0.0.
- CI 목표 달성 기록: fast lane ≤ 8분, coverage gate ≤ 12분, 호환 계약 ≤ 12분(C1 표로 증명).
