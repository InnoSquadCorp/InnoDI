# InnoDI 6.0.0 — final hardening

Status: implementation in progress; not release approval.
Baseline: `bd6412a98a7eec1c2e32f8d27c41139d8dedaf39`, PR #41.

## Decisions and boundaries

- R02 / D-H02: the user selected rejection of cyclic dependency graphs,
  including `Lazy` and `Provider`, on 2026-09-22. Deferred construction and
  detached handles remain supported for acyclic graphs. Weakening handles or
  adding an explicit scope-close obligation was not selected.
- Cycles retain resolver contexts even before first resolution. Reject them
  before generation, including with `validateDAG: false`; retain independent
  declaration-order and effect diagnostics. Test direct, deferred, mixed,
  self, and multi-node cycles, plus acyclic escaped-handle lifetime.
- Migration must preserve concurrent edits, not merely narrow the race with
  another pre-rename check. Conflict recovery must keep user bytes available.
  R01 uses atomic exchange with retained recovery entries, including on normal
  success. No automatic conflict overwrite or non-atomic fallback is permitted.
  Closing editors and reviewing/removing recovery files is explicit user work.
  R09 preserves POSIX modes; broader ACL/xattr preservation is not claimed.
- Retry must reject unsafe participation before changing any generation.
  R04 / D-H03 uses scope-owned reservations in stable provider-ID order across
  overlapping plans. Custom providers without the private transaction contract
  are rejected before mutation, rather than sequentially invoking arbitrary
  throwing resets. No global registry or unchecked concurrency is introduced.
- Mulbyul is the only consumer in scope, test-only in isolation. Do not change
  its source, dependency pins, project artifacts, or existing worktree state.
- No merge, tag, release, reduced gate, or toolchain-floor increase is approved.
